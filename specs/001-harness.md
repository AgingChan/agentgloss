# 001 — Harness and build

## Purpose

Provide the local autonomous-development harness requested from `sotto/harness`, adapted to a Rust/TDD project.

## Requirements

- `init.sh` checks the Rust toolchain, state files, task JSON, and runs `cargo check` once source exists.
- `scripts/env.sh` provides the build environment: conda `rustbuild` GCC for host build scripts, `~/.cargo/bin` on PATH, and the host linker override.
- `.cargo/config.toml` targets `x86_64-unknown-linux-musl` with `rust-lld` and self-contained linking.
- `harness/PROMPT.md` defines the session protocol: orient, setup, baseline, one task, TDD, implement, update state, clean exit.
- `harness/gate.sh` validates task state, checks placeholders, runs fmt, clippy, and tests.
- `harness/loop.sh`, `plan.sh`, `qa.sh`, `report.sh`, `add-task.sh` mirror the sotto harness and use the `claude` CLI where required.
- `state/tasks.json` follows `harness/templates/task-schema.json`; tasks are never removed or reordered.
- `state/progress.md` is updated every session; `state/fix_plan.md` is regenerated by `plan.sh`.

## Acceptance

- `./init.sh` exits 0.
- `./harness/gate.sh` exits 0 with a clean working tree (warnings allowed).
- `bash -n` passes for every harness script.
- `cargo run -- --version` prints a version once the CLI exists.
- The release binary is statically linked (`file target/.../agentgloss` reports static-pie).

## Tests

- Shell syntax checks against all harness scripts.
- Gate run with a valid state and with a deliberately invalid task JSON (must fail).
- Task schema validation via `python3 -m json.tool`.
