# 006 — TUI layout, input, navigation, and editing

## Layout

- Header (1 line): `mdreview  <file>  round N  open N  [VIM|STD]`.
- Footer (2 lines): status message and context key hints.
- Body: document view; optional outline and review panels.
- Responsive rules:
  - `width >= 110`: outline 26 columns left, review 34 right, document center.
  - `80 <= width < 110`: document full width; the focused panel appears as a side split (outline 26 or review 32).
  - `width < 80`: document full width; panels open as a full-screen overlay closed with `Esc`.
  - `height < 10`: show a "terminal too small" message; never panic.
- Document area uses rendered Markdown by default; `F3` toggles a raw-source view with line numbers.
- Media blocks reserve rectangles; the text pass never draws into them (spec 007).
- Commented lines show a marker in a 2-column review gutter.
- Review panel lists open, stale, and resolved items with kind, status, line, and excerpt.

## Input modes

- `vim` (default) and `standard`; selected by config/flag and toggled at runtime with `F2`.
- Key dispatch is mode-aware and exposed as `App::handle_key(KeyEvent)` for tests.
- The comment editor uses `edtui` in Vim mode and a standard multiline editor in standard mode; both support cursor movement, insert, backspace/delete, and Enter.
- `Esc` closes popups or cancels a selection. `q` quits after autosave (exit 1 if no signoff).

`/` opens a search prompt; typing filters case-insensitively, `Enter` jumps to the first match, `n`/`N` cycle, `Esc` closes. Search matches are highlighted in the document.

## Mouse

- Enabled by default; `--no-mouse` leaves the terminal's native selection intact.
- Click in the document moves the cursor; click-drag selects a line range; wheel scrolls three lines.
- Click a review-gutter marker opens the associated item.
- Click an outline heading or review item jumps to its source.
- Footer action labels (`Comment`, `Suggest`, `Resolve`, `Send`) are clickable.
- Hit-testing uses the current frame's layout rectangles; clicks outside known regions are ignored.

## Comment and suggestion flow

1. Select a line range, a block (`P`), or place the cursor on a line.
2. `c` opens a comment editor; `s` opens a suggestion editor with the selected source prefilled as `original`.
3. Saving creates an item anchored to the selected source range, autosaves the sidecar, and shows a status message.
4. `Enter` on a review item jumps to its anchor.
5. `x` resolves, `X` reopens, `d`/`Delete` deletes after confirmation.
6. Suggestions must use a contiguous source range; images accept comments but not suggestions.

## Signoff and exit

- `Ctrl+Enter` opens a confirmation: "Send N open items" or "Approve".
- Confirming writes the sidecar, sets `last_signoff` and optional approval, and exits the TUI.
- `q` or an external terminal close autosaves and exits aborted; no prompt is emitted.
- A corrupt sidecar is backed up; the TUI reports the recovery in the status line.
