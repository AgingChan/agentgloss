## Performance

- A generated 2,000-line Markdown fixture parses and lays out in under 1 second in a debug test; use a generous threshold to avoid flakiness.
- TUI rendering is viewport-only; no per-frame full-document layout except after width changes.
- Media decoding is off-thread; scrolling remains responsive while an image is pending.
- Cache lookups avoid re-decoding unchanged media.

## Manual checks

1. `./init.sh` and `./harness/gate.sh` pass.
2. `cargo run -- review tests/fixtures/spec.md` opens the TUI; add a comment; sign off.
3. `cargo run -- export tests/fixtures/spec.md` prints the numbered prompt and exits 10.
4. Re-run review after editing the spec; open comments survive and stale items are visible.
5. `agloss install claude` writes the command; `agloss install codex` writes the AGENTS block.
6. `agloss review --tmux` opens a popup inside a tmux session (manual).
7. Images render in Kitty/WezTerm; Terax falls back to half-blocks.
8. Mermaid renders with the Rust engine; invalid diagrams show source.
9. The VSIX installs in VS Code and the webview completes the request → comment → signoff → export flow.
10. SIGHUP/SIGTERM on a real PTY autosaves and restores the terminal.

## Release criteria

- `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, and `cargo test --all-features` pass.
- No top-level TODO/FIXME/unimplemented markers in `src/`.
- All tasks in `state/tasks.json` are `done` except documented blocked items.
- `harness/report.sh` shows 100% task progress.
- Release build produces a static musl binary.
- The QA pass (`harness/qa.sh`) has no critical or major findings.

## Known limitations to document

- Remote images are not fetched.
- tmux 3.2a cannot use Sixel passthrough; half-blocks are the safe fallback.
- Terax/xterm.js has no inline graphics protocol; half-blocks only.
- `mermaid-rs-renderer` is pre-1.0 and may differ from mermaid-cli; `mmdc` is the optional fidelity override.
- Full Vim emulation (macros, registers, ex commands) is out of scope.
